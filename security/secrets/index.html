    Secrets and keys

    Secrets and keys

    What is encrypted, what is write-only, what is redacted before it reaches a log, and the exact rotation procedure for each credential the platform holds.

    Verified against the checkout built for v2.2.4 · updated 20 Oct 2026

    On this page
    • The inventory
    • Encryption at rest
    • Write-only by contract
    • Redaction in logs
    • Rotation
    • What is not protected

    A forwarding platform necessarily holds the most sensitive credentials a user has: a Telegram session, a bot token, a model provider key. The design rule is narrow and applied consistently — a secret goes in, and it does not come back out. Not to a client, not to a log, not to an error message.

    The environment contract is a boolean map, not a values dump

    GET /api/system/env answers, for each recognised key, whether it is set and whether it is required, plus a hint that turns a missing key into an actionable next step. There is no route that returns a value, which is why the check is safe to leave reachable while an operator is debugging an install.

    Encryption at rest

    Cryptographic primitives and what each one guarantees
    DataPrimitiveProperty
    Session strings, tenant API keysAES-256-GCMAuthenticated: a modified ciphertext fails to decrypt rather than decrypting into something else.
    Account passwordsPBKDF2-SHA256, 240 000 iterations, per-row saltVerified in constant time; the iteration count is stored per row so it can be raised without invalidating old hashes.
    Configuration backupsAES-256-GCM bundle, key derived with PBKDF2-SHA256 at 600 000 iterationsPortable between hosts: export on one, import on the next. The bundle uses a higher iteration count than a password because its passphrase protects everything at once.
    Session backupsEncrypted archiveWritten only after the export succeeded; never in plaintext, not even transiently on disk.

    The key is the data

    Encrypted material is only as safe as ATF_ENCRYPTION_KEY. Lose it and the backups are gone; leak it and the database is readable. It belongs in a secret manager or an operator-held file with restrictive permissions, not in a compose file committed to git.

    Write-only by contract

    Four surfaces accept a secret and none of them read one back. The asymmetry is deliberate: a client that needs to know whether a key works calls the probe, and a client that needs to change one sends a new value.

    POST /api/ai-configsThe provider base URL, model and API key.The configuration with the key masked or omitted.

    POST /api/bot-tokensA bot token.The registration and its bot identity. The token is validated with Telegram first, then stored.
    POST /api/client/credentialsPersonal client credentials.Acceptance. There is no read route.

    A probe that refuses to ask

    The credential probe distinguishes "the provider said no" from "we refused to call it". A blocked endpoint is reported as ran: false with an error code, never as an unhealthy provider — so a tenant cannot use the probe to infer what exists on the host's private network.

    Redaction in logs

    Logs are where credentials leak by accident, so redaction is a single module used by every call site rather than a rule each author is trusted to remember:

    The access trail

    Each request is recorded with the verified actor and the correlation id — the id comes from the validated token, so a spoofed header cannot attribute an action to somebody else.

    Refusals are evidence

    A refused key or a rejected token is logged as a security-relevant warning. The access logger sits outside the API-key gate precisely so a bad key is not invisible.

    Rotation

    Rotation, and what each one interrupts
    CredentialHow to rotateBlast radius
    Bot tokenIssue a new token with BotFather, update ATF_BOT_TOKEN, restart the bot service.The bot goes offline until it restarts; queued deliveries resume.
    JWT secretSet the new value and restart the API.Every session ends at once — all users sign in again. Acceptable for a suspected compromise, disruptive otherwise.
    Encryption keyRe-encrypt before switching: export, import under the new key, then rotate the environment.Doing this in the wrong order makes existing ciphertext unreadable. There is no recovery path.
    Tenant AI keyPUT /api/ai-configs/{id} with the new key.Only that tenant's AI calls.
    Account passwordPATCH /api/auth/change-password with the old password.The account; a new login is required after expiry.
    Database passwordChange it in the database and in ATF_DB_PASSWORD, then restart the API and core together.Writes fail between the two restarts — do it in a maintenance window.

    • Bot token

      How to rotate
      Issue a new token with BotFather, update ATF_BOT_TOKEN, restart the bot service.
      Blast radius
      The bot goes offline until it restarts; queued deliveries resume.

    • JWT secret

      How to rotate
      Set the new value and restart the API.
      Blast radius
      Every session ends at once — all users sign in again. Acceptable for a suspected compromise, disruptive otherwise.

    • Encryption key

      How to rotate
      Re-encrypt before switching: export, import under the new key, then rotate the environment.
      Blast radius
      Doing this in the wrong order makes existing ciphertext unreadable. There is no recovery path.

    • Tenant AI key

      How to rotate
      PUT /api/ai-configs/{id} with the new key.
      Blast radius
      Only that tenant's AI calls.

    • Account password

      How to rotate
      PATCH /api/auth/change-password with the old password.
      Blast radius

      How to rotate
      Change it in the database and in ATF_DB_PASSWORD, then restart the API and core together.
      Blast radius
      Writes fail between the two restarts — do it in a maintenance window.

    What is not protected

    • !Transport inside the compose network. Containers speak plain gRPC and HTTP to each other. TLS is expected at the reverse proxy, and the network boundary is the container network.
    • !A stolen bot token is a stolen bot. Validation on registration proves the token works; it cannot prove who holds it later. Revoke with BotFather, then remove the registration.
    • !A Telegram session file is a logged-in client. That is why it is encrypted at rest and never returned by a list route — but on a running host, the decrypted material exists in memory for as long as the session does.
    • !The operator's own host. Root on the machine that runs the stack can read the environment and the database. No application-level control changes that.
