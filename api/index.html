    The control plane is a Go service that fronts the Python core. It owns authentication, tenancy, task CRUD, log history, dead-letter control and administration. Every route below is parsed out of api/main.go at build time, so this page cannot drift from the shipped binary.

    Authentication

    Two schemes exist and they do different jobs. Clients (the web dashboard and the mobile app) obtain a session token from the public authentication routes and send it as a bearer token. Machines that call the API server-to-server can present a shared key instead.

    Authentication schemes accepted by the control plane

    Unlinked accounts see nothing

    An account that exists but has not linked a Telegram account resolves to user id 0. Every tenant-scoped handler treats 0 as "own nothing" — the API returns an empty collection, never somebody else's data.

    Conventions

    • Versioned aliases. Health and system routes answer on both /api/… and /api/v1/…; the dashboard uses the mirrored forms.
    • Partial updates are explicit. PATCH carries only what changes plus update_mask, which is the only way to set a field to false, zero or empty.
    • Optimistic concurrency. Updating a task bumps its version, so a stale writer is rejected instead of silently overwriting.
    • Correlation ids. Every response carries a correlation id that also appears in the log history, so an API call and its delivery can be joined.
    • Bounded reads. Log and queue queries page with limit / since rather than returning unbounded history.
    • Generated schema. The per-task settings surface publishes its own JSON schema at /api/rules/settings/schema, so editors can be built before any task exists.

    Worked examples

    Group highlights

    System & readiness

    • GET /api/system/setupReady verdict, version, env contract and live service probes (booleans only)
    • GET /api/system/setup?probe=0The same verdict without probing the services
    • GET /api/system/envConfiguration contract: every key with set:true/false and a fix hint
    • GET /api/health/servicesPer-service reachability, latency and detail (core / logger / api / web)
    • GET /healthzLiveness probe used by the gateway and the upgrade gate

    Tasks & rules

    • GET /api/rulesList the caller's tasks (tenant-scoped)
    • POST /api/rulesCreate a task with a source list, a target list and a content policy
    • GET /api/rules/{id}Read one task including its resolved settings
    • PUT /api/rules/{id}Update a task (optimistic concurrency, version bumped)
    • DELETE /api/rules/{id}Delete a task and its schedules
    • POST /api/rules/{id}/pausePause a task: queued jobs defer instead of failing
    • POST /api/rules/{id}/resumeResume a task and unblock retry-wait jobs
    • POST /api/rules/{id}/toggleEnable or disable a task
    • POST /api/simulateDry-run a message through a task and see the decision

    Task lifecycle (async jobs)

    • GET /api/tasksList the caller's async jobs (state machine, tenant-scoped)
    • POST /api/tasksSubmit an async job (session backup, DLQ replay/purge, backup export); idempotent via idempotency_key
    • GET /api/tasks/{id}Poll one job: state, attempt, timestamps, structured error details
    • POST /api/tasks/{id}/cancelCancel a queued job before a worker claims it
    • POST /api/tasks/{id}/retryRe-queue a failed job (attempt budget reset)

    Sessions

    • GET /api/sessionsList the caller's Telegram sessions
    • GET /api/sessions/{id}/chatsList the chats a session can see (sources and targets)
    • POST /api/sessions/{id}/backupExport an encrypted session backup
    • POST /api/backup/exportExport an encrypted backup of sessions and settings
    • POST /api/backup/importRestore from an encrypted backup
    • DELETE /api/sessions/{id}Terminate a session and purge its credentials

    Filters & AI

    • GET /api/filtersList filter rules
    • POST /api/filtersCreate a filter rule
    • PUT /api/filters/{id}Update a filter rule
    • DELETE /api/filters/{id}Delete a filter rule
    • GET /api/ai-configsList AI rewrite configurations
    • POST /api/ai-configsCreate an AI configuration (provider, model, prompts)
    • PUT /api/ai-configs/{id}Update an AI configuration
    • POST /api/prompts/testSend sample text through a rewrite prompt

    Observability

    • GET /api/logs?service=&level=&search=&limit=&since=Query attributable log history with bounded paging
    • GET /api/logs/statsAggregate counts by service and level
    • GET /api/logs/policyWhich levels and services the engine admits
    • POST /api/logs/purgePurge log history for one of the caller's own tasks (the installation-wide purge is administrator-only)
    • GET /api/statsDelivery throughput and outcome counters
    • GET /api/queueQueue depth and in-flight jobs
    • GET /api/dlqDead-lettered jobs
    • POST /api/dlq/{id}/retryReplay a dead-lettered job
    • DELETE /api/dlqPurge dead-lettered jobs for the caller scope (answers with the number removed)

    Delivery lifecycle

    Every delivery moves through these states, and the same vocabulary is used by the queue API, the log history and the dashboard. Jobs in RETRY_WAIT are the ones a pause defers rather than fails.

    • RECEIVED
    • VALIDATING
    • AUTHORIZED
    • ACCEPTED
    • IN_PROGRESS
    • RETRY_WAIT
    • SUCCEEDED
    • FAILED
    • CANCELLED
    • OUTCOME_UNCONFIRMED

    Errors & status codes

    Status codes returned by the control plane
    CodeWhenWhat to do
    200Success.Read the JSON body.
    400The body or query is malformed.Check the settings schema and the environment contract.
    401Missing, expired or unverifiable token.Log in again, or run atf auth whoami.
    403Administration route called without admin rights.Use an administrator account.
    404The resource does not exist — or does not belong to you.Ownership failures deliberately look identical to missing rows.
    409A concurrent update moved the version first.Re-read the task, re-apply your change.
    422A setting was rejected by validation.Read the field error in the response body.
    502The logger or core service is unreachable.Check /api/health/services and atf doctor.
