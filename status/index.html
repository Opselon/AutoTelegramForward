    This page does not have an opinion about what is finished. It renders the catalog the repository maintains for itself: docs/feature_catalog.json, read at build time and shown verbatim. 18 features are listed — each one either implemented, partially implemented, or planned.

    2Partial

    The three counts sum to 18. A row is implemented only when the catalog records IMPLEMENTED for it; anything the catalog marks PARTIALLY_IMPLEMENTED or NOT_IMPLEMENTED is shown as partial or planned here, with the reason.

    Implemented 14

    Shipped and reachable through the clients and entry points the catalog names. Where a completion condition is recorded, it is what the feature had to prove to leave this list.

    • Create forwarding ruleImplementedwebbotmobileminiapp

      Completion condition: rule row committed with generated id and owner_user_id

    • Update forwarding rule (optimistic concurrency)Implemented

      Completion condition: version-bumped UPDATE committed; version conflict returns explicit error

    • Pause/resume rule with durable queue semanticsImplemented

      Completion condition: paused rules never forward new messages; queued jobs deferred with backoff; resume unblocks RETRY_WAIT jobs

    • Durable message forwarding pipelineImplemented

      Completion condition: Telegram API confirms delivery (target_msg_id > 0); UNKNOWN on timeout; DLQ after max retries

    • Branding hop (A -> C -> B) composed with every message transformImplemented

      Completion condition: the processed message is posted into C once per deliverable and the target receives a forward of C; transforms run exactly once (never skipped or doubled by the worker); any hop failure falls back to a direct A -> B delivery

    • SHA-256 content fingerprint deduplicationImplemented

      No completion condition recorded in the catalog.

    • Keyword-triggered reply add-onImplemented

    How this list is produced

    The single source of truth is docs/feature_catalog.json at the root of the repository. On every build, scripts/sync-repo-content.mjs reads that file and writes it intosrc/data/repo-info.json as featureCatalogDetail and featureCatalogStatus, which this page reads directly. No feature name, status or count on this page is typed by hand, so the site cannot claim more than the repository does.
