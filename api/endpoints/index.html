    Endpoint reference

    Every one of the 102 routes the control plane registers: verb, path, auth level, the fields each one accepts and a real response body.

    On this page
    • How to read a route
    • What each group is scoped to
    • All 102 routes

    The table on this page is not typed by hand. api/main.go is parsed at build time, including the routes registered through middleware, so the list is exactly what the binary under test registers — 102 routes across 4 groups. Each one carries what it accepts and what it answers.

    Filter by verb

    The verb chips under the search box are toggles: press POST and PUT to see only the routes that change something.

    Filter by anything else

    The search box matches the path, the handler name, the summary and every accepted field — searchidempotency and only the routes that take one remain.

    No JavaScript?

    Every card is rendered on the server. Filtering is an enhancement, so the full table is present and linkable with scripting disabled.

    What each group is scoped to

    Service health & system

    12 routes

    The unauthenticated surface an operator, a load balancer or the upgrade gate calls: liveness, readiness, the version block, the environment contract and the live probe of every service in the chain. These routes answer without a token because they must be callable precisely when authentication is the thing that is broken.

    Scope · public probe

    Authentication

    7 routes

    Public by definition — this is where a caller stops being anonymous. Three ways in: username and password, a single-use code the bot hands to an already-verified Telegram user, or signed Mini App init data. Every route here is inside the authentication rate class, so the brute-force budget is enforced before a token is ever minted.

    Scope · public, rate-limited

    Authenticated control plane

    71 routes

    The tenant surface. Each call resolves the caller from the verified token and then queries only that identity’s rows; an owner id in the body is never read. A row that belongs to somebody else is reported as missing, so ids cannot be probed.

    Scope · tenant-scoped

    Administration

    12 routes

    Installation-wide operations. The route is wrapped in the administrator gate, and the core re-checks the role on the other side of gRPC, so a forged or stale admin claim fails twice.

    Scope · administrator only

    All 102 routes

    Grouped by the mux that owns them, in registration order, with the mount prefixes already applied. Statuses are the ones each handler can return; the shared envelope is described in the response reference.

    GET

    /api/health/services

    Publich.ServicesHealth

    Live reachability of every service in the chain — core (gRPC channel plus pipeline loop), logger, web and this process — probed in parallel with short timeouts.

    Auth
    No credential — public probe or login exchange
    Scope
    No identity and no tenant data — deployment-level facts only.
    Statuses
    200
    Note
    The overall status is "healthy" only when every probe answers; a single failure degrades the whole stack to "degraded" with a per-service detail.

    Authentication

    7 routes · public, rate-limited

    Public by definition — this is where a caller stops being anonymous. Three ways in: username and password, a single-use code the bot hands to an already-verified Telegram user, or signed Mini App init data. Every route here is inside the authentication rate class, so the brute-force budget is enforced before a token is ever minted.

    GET

    /api/auth/bot-login-link

    Publich.AuthBotLoginLink

    Mints the caller’s own single-use dashboard login code and returns the relative link to open. Requires a valid Bearer token — the code is minted for the identity the token proves, never for an id in the request.

    Auth
    No credential — public probe or login exchange
    Scope
    Anonymous caller; the response is what establishes identity.
    Statuses
    200 · 401 · 429
    Note
    A 60-second per-user cooldown applies: while a code is live and unused the endpoint answers 429 with Retry-After instead of minting another, so a double click cannot invalidate the link that was just handed out. Codes die after 10 minutes or one use.

    Versioning and aliases

    • Two contract versions are exposed on purpose. The product version (2.2.4) moves with releases; the API contract version stays at 1.0.0 until a breaking change lands.
    • Probes answer on both shapes. Health and system routes exist under/api/… and /api/v1/…; the versioned form is what the mobile client pins.
    • Clients negotiate before they call. Read /api/version and check min_supported_client plus the features keys instead of probing endpoints for their presence.
    • The shipped schema is authoritative. The API serves its own OpenAPI document at /api/openapi.yaml, baked into the image next to the code that serves it.

    Generate a client, then check it against the gate

    Fetch /api/openapi.yaml from a running deployment and point a generator at it. The route table on this page is parsed from the same source as that document, so both move together; the response reference explains the envelope every generated client still has to unwrap.
