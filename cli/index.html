    CLI

    CLI reference

    The atf command line: 24 command groups covering installation, task control, log history, backups, diagnostics, releases and continuous supervision.

    On this page
    • How it works
    • Everyday workflows
    • All command groups
    • Scripting with --json

    atf is the operator interface to the whole installation: it installs, validates, diagnoses, controls tasks, reads log history, exports backups, regenerates gRPC stubs and supervises the running stack. Everything the dashboard can do, the CLI can do — and it can do it from a cron job.

    24 command groups61 gRPC methods behind it64 test filesJSON output on demand

    How it works

    Conventions worth knowing

    • Task ids accept the short prefix shown by atf rules list.
    • --json is available on the read commands and is what scripts should parse.
    • atf validate is read-only; --strict turns warnings into failures for CI.
    • atf doctor --fix repairs what it can and reports what it cannot.

    Everyday workflows

    1 · Install and verify

    1. atf setup
    2. atf status
    3. atf validate --strict
    4. atf doctor

    The wizard builds the stack, then proves each service is serving before it exits.

    2 · Connect Telegram

    1. atf config set ATF_BOT_TOKEN
    2. atf auth token --save
    3. atf sessions list

    Sessions are listed tenant-scoped; backups are encrypted before they touch disk.

    3 · Create your first task

    1. atf rules create --name "News" --source -1001111111111 --target -1003333333333
    2. atf rules list
    3. atf rules settings set <id> clean_links=true
    4. atf rules simulate <id> --text "BUY NOW t.me/spam"

    Simulate runs the full pipeline on text you supply — nothing is sent to Telegram.

    4 · Watch it work

    1. atf logs tail --follow -n 50
    2. atf logs stats
    3. atf data queue
    4. atf data dlq --replay

    The queue and dead-letter views are the same data the dashboard shows.

    5 · Upgrade with a gate

    1. atf system upgrade
    2. atf release verify
    3. atf deploy --build

    The upgrade path checks readiness and refuses to proceed on a failing stack.

    All command groups

    Read from the argument parser at build time, so this list is exactly what your binary accepts.

    atf setup

    Guided wizard: detect the platform, validate every answer, build, then prove each service is serving

    • atf setup
    • atf setup --check
    • atf setup --yes
    • atf setup --answers answers.json

    atf status

    Live service board with ports, reachability, task counts and the dashboard URL

    • atf status
    • atf status --watch

    atf system

    Stack lifecycle plus boot persistence and the full upgrade path

    • atf system services
    • atf system upgrade
    • atf system service install

    atf validate

    Read-only checks: layout, env, compose, catalog parity, secrets scan, database, proto, ports

    • atf validate
    • atf validate --runtime
    • atf validate --strict --json
    • atf validate --deep

    atf doctor

    Deep diagnosis across DB, binaries, ports and gRPC, with --fix to repair

    • atf doctor
    • atf doctor --fix

    atf rules

    Task control: list, show, create, update, clone, enable/disable, pause/resume, sources, path, simulate, settings

    • atf rules list --json
    • atf rules sources <id> add <chat>
    • atf rules simulate <id> --text "hello"
    • atf rules settings set <id> clean_buttons=true

    atf logs

    Log archive access from the terminal: tail, query, search, stats, export, purge

    • atf logs tail --follow -n 50
    • atf logs query --level ERROR
    • atf logs stats

    atf data

    Queue and DLQ inspection, aggregate stats, encrypted backup export / import

    • atf data queue
    • atf data dlq --replay
    • atf data backup-export --out atf.atf

    atf sessions

    Telegram session inventory, encrypted backup and terminate

    • atf sessions list
    • atf sessions backup --out session.bak

    atf auth

    Dashboard / API authentication for the CLI itself

    • atf auth token --save
    • atf auth whoami

    atf admin

    Administration: users, admins, settings, extensions, broadcast, overview

    • atf admin overview
    • atf admin users list
    • atf admin broadcast --text "maintenance"

    atf config

    Read and write configuration values with validation

    • atf config list
    • atf config set ATF_BOT_TOKEN

    atf db

    Database inspection, integrity status, snapshot and backup

    • atf db status
    • atf db snapshot

    atf docker

    Compose lifecycle for the four containers

    • atf docker up
    • atf docker ps
    • atf docker logs core

    atf deploy

    Build, recreate and verify in one gated command

    • atf deploy --build

    atf certs

    TLS certificate inspection, expiry checks and renewal

    • atf certs check
    • atf certs renew

    atf net

    Network inspection and the AI bridge reconnect path

    • atf net inspect
    • atf net reconnect

    atf platform

    Host detection plus the exact docker install commands for this distribution

    • atf platform
    • atf platform --json

    atf release

    Version, manifest, verification and the portable single-file build

    • atf release version
    • atf release verify
    • atf release portable

    atf ci

    Pipeline status, logs and live watch for GitHub Actions runs

    • atf ci status
    • atf ci watch

    atf i18n

    Cross-language catalog audits: parity, placeholders and RTL leakage

    • atf i18n

    atf proto

    Regenerate and verify gRPC stubs against the .proto sources

    • atf proto

    atf test

    Run the test suites: python, go, flutter or all

    • atf test py
    • atf test all

    atf watch

    Continuous supervision of the running stack

    • atf watch

    Scripting with --json

    Same data, two surfaces

    Logs, queue depth, delivery stats and dead-lettered jobs are readable through the CLI and the REST API. Pick whichever fits the script; both are tenant-scoped.
